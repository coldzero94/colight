## 1. URL 파싱 실패 시나리오

> 채용공고 URL → 자동 파싱은 핵심 진입점. 실패 시 이탈률 직결

### 시나리오 매트릭스

| 시나리오 | 감지 시점 | 사용자 메시지 | 대응 UX |
|----------|----------|--------------|---------|
| 지원하지 않는 사이트 URL | URL 입력 즉시 | "현재 잡코리아, 원티드, 캐치, 사람인을 지원합니다" | 수동 입력 폼 제공 + 지원 사이트 추가 요청 링크 |
| URL 형식 오류 | 입력 중 실시간 | "올바른 URL 형식이 아닙니다" | 실시간 유효성 검증 (debounce 300ms) |
| 사이트 구조 변경 파싱 실패 | 파싱 단계 | "자동 분석에 실패했습니다. 다시 시도합니다..." | AI 폴백 파싱 시도 → 실패 시 수동 입력 안내 |
| 크롤링 차단/403 | 파싱 단계 | "해당 공고에 접근하기 어렵습니다" | 재시도 1회 후 수동 입력 폼 제공 |

### URL 파싱 처리 흐름

```
[URL 입력]
    │
    ├── URL 형식 검증 (실시간, debounce 300ms)
    │     └── 실패 → 인라인 에러 메시지
    │
    ├── 도메인 화이트리스트 확인
    │     └── 미지원 도메인 → "현재 지원하는 사이트" 안내 + 수동 입력 폼
    │
    ▼
[크롤링 시도]
    │
    ├── 성공 → 파싱 진행
    │
    ├── 403/차단 → 재시도 1회 (User-Agent 변경)
    │     ├── 성공 → 파싱 진행
    │     └── 실패 → 수동 입력 폼 전환
    │
    └── 파싱 실패 (구조 변경) → AI 폴백 파싱 (원문 텍스트 → LLM 구조화)
          ├── 성공 → 결과에 "AI 자동 분석 결과입니다. 내용을 확인해주세요" 배너
          └── 실패 → 수동 입력 폼 + "공고 내용을 직접 붙여넣어 주세요"
```

### 수동 입력 폼 구성

| 필드 | 필수 여부 | 설명 |
|------|----------|------|
| 기업명 | 필수 | 텍스트 입력 (자동완성 지원) |
| 직무/포지션 | 필수 | 텍스트 입력 |
| 주요 업무 | 선택 | 텍스트에어리어 |
| 자격 요건 | 선택 | 텍스트에어리어 |
| 우대 사항 | 선택 | 텍스트에어리어 |
| 자소서 문항 | 선택 | 다중 입력 (문항별 추가) |

## 2. AI API 장애 시나리오

> AI 분석/코칭은 핵심 가치. 장애 시에도 사용자 신뢰를 유지해야 함

### Claude API 장애

| 상황 | 타임아웃 | 대응 | 사용자 메시지 |
|------|---------|------|--------------|
| 응답 지연 | 30초+ | 프로그레스 바 유지 | "분석이 평소보다 오래 걸리고 있습니다..." |
| 응답 지연 | 60초+ | 재시도 버튼 표시 | "다시 시도하시겠어요?" + 재시도 버튼 |
| 500 에러 | 즉시 | 자동 재시도 (최대 2회, 지수 백오프) | "잠시 문제가 발생했습니다. 자동으로 재시도합니다..." |
| 자동 재시도 실패 | 3회 실패 후 | 수동 재시도 + 캐시 제공 | "잠시 후 다시 시도해주세요" + 이전 분석 결과 캐시 제공 |
| Rate Limit (429) | 즉시 | 큐잉 처리 | "대기 중입니다 (예상 대기 시간: ~30초)" |

### OpenAI API 장애 (GPT-4.1 mini)

```
[GPT-4.1 mini 장애 감지]
    │
    ├── 공고 파싱 → Claude Haiku 폴백 (비용 증가 ~5배, 기능 유지)
    ├── 무기 태깅 → Claude Haiku 폴백
    ├── 임베딩 생성 → 키워드 기반 매칭으로 폴백 (품질 저하 감수)
    └── AI 인터뷰 → Claude Haiku 폴백
```

> **폴백 전략 원칙**: 비용이 증가하더라도 기능 중단보다는 폴백 우선. 폴백 발생 시 Slack 알림으로 모니터링.

### 재시도 정책 (Backend)

```
지수 백오프 정책:
  - 1차 재시도: 1초 대기
  - 2차 재시도: 3초 대기
  - 3차 재시도: 없음 (사용자에게 수동 재시도 위임)

재시도 대상:
  - 500, 502, 503 에러
  - 타임아웃 (30초 초과)

재시도 비대상:
  - 400 Bad Request (프롬프트 이슈)
  - 401 Unauthorized (API 키 이슈 → 즉시 알림)
  - 429 Rate Limit (큐잉으로 처리)
```

## 3. 채용공고 관련 시나리오

> 공고 자체의 상태나 품질 문제

### 시나리오별 대응

| 시나리오 | 감지 방법 | 대응 UX |
|----------|----------|---------|
| 공고 마감 | 파싱 시 마감일 확인 / 페이지 상태 감지 | 분석 진행 + "이 공고는 마감되었을 수 있습니다" 경고 배너 (주황색) |
| 공고 내용 부족 (제목만 있음) | AI 파싱 결과 필드 2개 이하 | "충분한 정보가 없어 기본 분석만 제공합니다" + 수동 보완 유도 |
| 동일 기업 중복 분석 | company_analysis_cache 조회 (7일 TTL) | "이전 분석 결과를 사용합니다 (분석일: 2/10)" + "새로 분석하기" 옵션 |
| 채용 시즌 외 공고 | 공고 날짜가 6개월 이상 이전 | "오래된 공고입니다. 기업 정보가 현재와 다를 수 있습니다" 안내 |
| 비정규직/인턴 vs 정규직 혼동 | AI 파싱 시 고용형태 추출 | 분석 결과에 고용형태 명확히 표시 |

### 캐시 전략

```
[기업 분석 요청]
    │
    ├── 캐시 존재 (7일 이내) + 동일 직무
    │     → "이전 분석 결과를 사용합니다"
    │     → [새로 분석하기] 버튼 (크레딧 차감됨을 안내)
    │
    ├── 캐시 존재 (7일 이내) + 다른 직무
    │     → 기업 정보는 캐시 활용, 직무 분석만 새로 실행
    │     → 크레딧 0.5회 차감
    │
    └── 캐시 없음 or 만료
          → 전체 분석 실행
          → 크레딧 1회 차감
```

## 4. 사용자 한도 관련 시나리오

> Freemium 모델의 핵심. 페이월은 자연스럽되, 무료 사용자도 가치를 느끼게

### 한도 초과 대응 매트릭스

| 한도 | 무료 | 스타터 | 프로 | 초과 시 UX |
|------|------|--------|------|-----------|
| 경험 등록 | 3개 | 무제한 | 무제한 | 소프트 페이월 |
| 기업 분석 | 1회 | 10회 | 30회 | 결과 미리보기 (블러) |
| AI 코칭 | 1회 | 10회 | 30회 | 결과 미리보기 (블러) |
| 일일 사용량 캡 | - | 5회/일 | 15회/일 | 내일 초기화 안내 |

### 소프트 페이월 UI 설계

```
[무료 한도 초과 시]
    │
    ├── 기업 분석 초과
    │     → 분석 결과 상단 30%만 표시
    │     → 나머지 블러 처리 + 그라데이션 오버레이
    │     → "전체 분석 결과를 확인하려면 스타터 회원으로 업그레이드하세요"
    │     → [스타터 시작하기 (4,900원)] CTA 버튼
    │
    ├── 경험 등록 초과
    │     → "추가 경험 등록은 스타터 회원부터 가능합니다"
    │     → [현재 경험으로 계속하기] + [스타터 시작하기] 버튼 병렬 배치
    │     → 현재 경험만으로도 서비스 이용 가능함을 강조
    │
    └── 일일 사용량 캡 도달
          → "오늘의 사용 한도에 도달했습니다"
          → 잔여 한도 표시: "오늘 5/5회 사용 완료"
          → "내일 오전 6시에 초기화됩니다"
          → 프로 요금제 안내 (일일 15회)
```

### 한도 도달 사전 안내

| 시점 | 안내 메시지 | 위치 |
|------|-----------|------|
| 잔여 2회 | "무료 분석이 2회 남았습니다" | 대시보드 상단 배너 (닫기 가능) |
| 잔여 1회 | "마지막 무료 분석입니다. 소중하게 사용하세요!" | 분석 시작 전 확인 모달 |
| 잔여 0회 | "무료 분석을 모두 사용했습니다" | 분석 버튼 비활성화 + 업그레이드 안내 |

## 5. 분석 대기 시간 UX

> 15~30초 대기 구간은 사용자 이탈의 고비. 적극적 피드백으로 몰입 유지

### 단계별 프로그레스 표시

```
[분석 시작]
    │
    ├── 0~5초: 크롤링 단계
    │     ● ○ ○ ○  "채용공고를 분석하고 있습니다..."
    │     프로그레스 바: 0% → 20%
    │
    ├── 5~10초: 데이터 수집 단계
    │     ● ● ○ ○  "기업 정보를 수집하고 있습니다..."
    │     프로그레스 바: 20% → 50%
    │     서브텍스트: "DART 기업정보, 최근 뉴스를 수집 중"
    │
    ├── 10~25초: AI 분석 단계
    │     ● ● ● ○  "AI가 종합 분석 중입니다..."
    │     프로그레스 바: 50% → 90%
    │     서브텍스트: "인재상, 전략 키워드를 도출하고 있습니다"
    │
    └── 25~30초: 마무리 단계
          ● ● ● ●  "분석 결과를 정리하고 있습니다..."
          프로그레스 바: 90% → 100%
```

### 스트리밍 UI

AI 분석 결과가 실시간으로 생성되는 구간 (10~25초):

```
┌─────────────────────────────────────────┐
│ 삼성전자 - 마케팅 직무 분석              │
│                                         │
│ ■ 인재상 분석                           │
│   1. 창의적 사고: 새로운 마케팅 채널을   │
│      개척하고 데이터 기반으로...█        │  ← 타이핑 커서 애니메이션
│                                         │
│ ■ 전략 키워드                           │
│   (분석 중...)                          │  ← 스켈레톤 UI
│                                         │
│ ■ 내 경험 매칭                          │
│   (대기 중)                             │  ← 비활성 상태
└─────────────────────────────────────────┘
```

### 대기 중 팁 카드

분석 대기 중 하단에 표시되는 "알고 계셨나요?" 카드:

| 카테고리 | 예시 콘텐츠 |
|----------|-----------|
| 자소서 팁 | "자소서에서 '노력했습니다'보다 '매출 15% 증가시켰습니다'가 3배 더 높은 통과율을 보입니다" |
| 기업 분석 팁 | "기업의 최근 뉴스를 자소서에 녹이면 '관심도 높은 지원자'로 인식됩니다" |
| 무기 시스템 팁 | "리더십 무기가 부족하다면, 스터디 조장이나 조별과제 리딩 경험도 좋은 소재가 됩니다" |
| 면접 연계 팁 | "자소서에 쓴 경험은 면접에서 80% 확률로 질문받습니다. 본인이 깊이 아는 경험을 쓰세요" |

> 팁 카드는 랜덤으로 1개씩 표시, 3초마다 페이드 전환. 닫기 가능.

### 에러 발생 시 대기 화면 전환

```
[분석 중 에러 발생]
    │
    ├── 프로그레스 바 → 일시 정지 (주황색으로 변경)
    ├── 메시지: "잠시 문제가 발생했습니다. 자동으로 재시도합니다..."
    │
    ├── 재시도 성공 → 프로그레스 바 재개 (초록색 복귀)
    │
    └── 재시도 실패
          → 프로그레스 바 → 빨간색
          → "분석에 실패했습니다"
          → [다시 시도] + [수동 입력으로 진행] 버튼
```

## 6. 네트워크 & 일반 에러

### 네트워크 에러 처리

| 상황 | 감지 | 대응 |
|------|------|------|
| 오프라인 | `navigator.onLine` + fetch 실패 | 상단 배너: "인터넷 연결을 확인해주세요" (자동 감지/복구) |
| 느린 네트워크 | 응답 5초 초과 | 로딩 인디케이터 + "연결이 느립니다" |
| 세션 만료 (401) | API 응답 | 자동 토큰 갱신 시도 → 실패 시 로그인 페이지 리다이렉트 |
| 서버 점검 (503) | API 응답 | 전체 화면 점검 안내 페이지 |

### 에러 토스트 디자인 원칙

1. **사용자 탓이 아님을 명시**: "오류가 발생했습니다" (O) / "잘못된 입력입니다" (X)
2. **다음 행동을 안내**: 에러 메시지 + 해결 방법 항상 함께
3. **기술 용어 배제**: "500 Internal Server Error" (X) → "잠시 문제가 발생했습니다" (O)
4. **재시도 가능 여부 명시**: 재시도 가능한 에러는 항상 [다시 시도] 버튼 포함
5. **데이터 유실 방지**: 폼 입력 중 에러 시, 입력 데이터 localStorage에 자동 저장
