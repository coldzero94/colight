## 읽기 순서

1. **01 문제 정의** → 왜 만드는지
2. **02 핵심 기능** → 무엇을 만드는지
3. **03 기능 스펙** → 어떻게 동작하는지 (상세)
4. **05 기술 아키텍처** → 어떤 기술로 만드는지
5. **04 비즈니스** → 어떻게 성장시키는지
6. **06 에러 시나리오** → 실패 시 어떻게 대응하는지
7. **07 온보딩** → 사용자를 어떻게 유입시키는지
8. **08 법적 사항** → 법적으로 무엇을 준비해야 하는지
9. **09 시장 분석** → 시장에서 어떻게 경쟁하는지
10. **10 Fair Use** → 사용량을 어떻게 제한하는지
11. **11 알림 시스템** → 사용자에게 어떻게 알림을 보내는지
12. **12 리텐션 전략** → 사용자를 어떻게 유지하는지

## Critical Path

```
F01(경험 등록) → F03(무기 태깅) → F07(공고 분석) → F08+F09(기업 분석)
    → F10(적합도 매칭) → F11(문항 분석) → F12(경험 추천)
    → F13(초안 코칭) → F14(첨삭 코칭)
```
